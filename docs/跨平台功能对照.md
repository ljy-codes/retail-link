# Windows 与 macOS 功能对照

核对日期：2026-11-27，Asia/Shanghai。当前工作区 Windows 0.2.10 本地候选；Mac 0.2.9 为配对源码版本，未虚构新 Mac DMG 或实机通过记录。

## 结论与证据边界

- 当前两端构建入口复用同一个 `server.py`、`backend/`、`web/` 和 37 项功能清单；实际 Windows 展开载荷与本轮生成的 Mac 布局共享载荷共 31 个文件，其逐文件大小、SHA-256 和 manifest 原字节完全一致。
- 宿主Python3.14与内置Python3.12全量回归均输出 `Ran 319 tests / OK (skipped=8)`，无失败；跳过包含1个Mac测试类，方法级计数为312通过、7跳过。Node界面57项通过；Windows候选程序已真实启动并收到 `frontendReady`，健康接口、单实例和宿主终止后的后端回收通过。
- 本轮没有 Mac 环境。Mac 布局复制与静态契约核对只证明共享代码和功能入口一致，不能证明 Swift 编译、系统面板、安装升级、废纸篓和磁盘行为已经实机通过。当前不能宣称两个已交付二进制全面一致。
- 整理前的 `origin/macos` 缺少数据健康模块及页面，源写回 UTF-8 读取和刷盘实现也较旧。用户随后授权正常推送GitHub，本次将统一源码先纳入 `main`，再以正常合并同步 `windows`、`macos`；既有 Mac 包及已发布标签不变，源码同步不代表 Mac 二进制已重建。

原始证据：工作区 `工作记录/跨平台-共享载荷.json`、`python-最终.log`、`windows-构建.log`、`windows-原生自测.json`。测试状态以 [test.md](test.md) 为准。

## 调用链与平台边界

共享业务调用链为 `web → server.py → backend → SQLite/JSON/本地文件`，没有 Redis、MQ、远端业务服务或 Java 事务。SQLite 事务、确认 token、源文件指纹、导出备份与排他发布沿用既有实现，本轮不改 schema、索引和业务口径。

| 边界 | Windows | macOS | 核对结果与限制 |
| --- | --- | --- | --- |
| 页面与业务算法 | WinForms/WebView2 加载共享页面与本地 Python | AppKit/WKWebView 加载共享页面与本地 Python | 31 个共享文件哈希相同；Windows 上回归通过 |
| 原生消息 | 注入 `webkit.messageHandlers.retailLinkDesktop`，返回 `RetailLinkDesktop.resolve` | 原生同名桥接与同名回调 | `chooseDirectory/chooseFile/saveFile/showInFolder/frontendReady` 均有处理；只信任当前本地服务来源 |
| 用户路径 | LocalAppData、Documents、临时就绪目录 | Application Support、Documents、临时就绪目录 | 不依赖随机端口；设置保存在后端；用户数据位于程序外 |
| 程序资源保护 | 整个安装根目录 | 整个 `.app` | 已补齐 Windows 安装根保护，禁止把数据或导出写进将被升级替换的位置 |
| 启动与失败 | PID/版本/本地地址核验、父管道、错误页与重试 | 对应 ready 核验、父管道、错误页与重试 | 已补 Windows 后端 URI 失效、缺运行时回收、渲染失败回收；隔离行为测试通过 |
| 下载保存 | 系统保存面板、同目录暂存、排他发布 | 系统保存面板、同目录暂存、排他发布 | 不覆盖已存在目标；系统面板及真实 FAT/exFAT 尚需分别验收 |
| 安装升级 | 用户可选路径、HKCU 登记、快捷方式、旧版恢复 | DMG/可选目录安装、签名核验、旧 App 恢复 | 实现允许不同；本轮没有运行安装器，不能将历史成功算作 0.2.10 安装通过 |
| 普通卸载 | 移除程序与入口，保留用户数据 | 移走当前 App，保留用户数据 | 功能目的相同；本轮只执行隔离数据清理块和实际本机残留清理 |
| 彻底卸载 | 白名单数据移至可恢复位置 | 白名单数据移至废纸篓 | Windows 补日记录库/模板，Mac 补导入会话；原件、导出、写回备份与未知文件保留 |
| 构建与交付 | `desktop/build/windows`、EXE + HTML | `desktop/build/macos`、DMG + HTML | 平台缓存隔离，统一共享载荷及大小限制，不互相清理 |

## 尚需人工或 Mac 环境完成

1. 在 Mac 上用本轮唯一源码编译 Swift、构建运行时与 DMG，核对真实包内 manifest；现有 Mac 0.2.1 交付不能自动获得本轮代码。
2. 用同一套合成工作簿在两台设备走完原生选择、保存、迁移、源写回备份恢复，比较导出的业务内容；不能仅比较 ZIP 字节或界面截图。
3. 由用户亲自安装 Windows 0.2.10，复验可选路径、中文空格路径、升级与普通/彻底卸载的界面体验，并检查右侧展示与独立窗口切换。此前“繁琐、启动慢、内存高”等人工反馈继续保留。
4. 补齐 first/cold/warm/idle/long-idle、真实移动盘与签名/公证验证；本轮不扩展功能、不自动发布或安装。
