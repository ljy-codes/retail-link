# 人工验收缺陷记录

更新日期：2026-11-24  
适用范围：零售通 macOS / Windows 桌面版  
职责边界：macOS 主导功能、业务口径与跨平台验收基线；Windows 负责 Windows 平台功能实现、平台验收和安装包交付。

## 强制准则

1. **安装路径必须可选，绝对不能写死。**
   - 安装器、卸载器、快捷方式、升级器和日志均不得各自维护一套固定路径。
   - 安装路径必须以安装时选择的路径为唯一事实来源，并写入可查询的安装登记信息。
   - 卸载、覆盖升级和启动必须读取实际安装位置，不能假定默认目录。
2. **安装自由，卸载方便。**
   - 用户可选择安装位置，但路径会带来权限、磁盘空间或非法目录时，必须明确提示并允许重新选择。
   - 卸载应能通过系统应用管理或开始菜单等常规入口完成，不要求用户手工查找目录、执行命令或删除文件。
   - 普通卸载应一次完成程序清理；需要保留的数据必须明确说明。
   - 卸载失败必须给出可理解的原因和非零退出码，不能静默退出或提示成功但实际未清理。
3. **安装与卸载行为必须对称。**
   - 安装器允许的路径，卸载器必须能够识别并卸载。
   - 安装器创建的快捷方式、卸载项、后台进程和平台注册信息，卸载器必须完整回收。
   - 默认路径卸载通过不代表自定义路径卸载通过，两种路径都必须验收。
4. **用户数据不能被安装或卸载误删。**
   - 原始资料、导入文件和用户生成文件不得因普通卸载、彻底卸载或升级而删除。
   - 完整卸载的范围必须可见、可恢复，并明确与普通卸载的区别。

### 用户验收结论

安装完成弹窗“太太太 low 了”。当前收尾流程像临时调试提示，不像正式交付给经营用户的产品。

### 实际现象

#### 1. GUI 安装器没有安装路径选择

- 普通用户双击安装包后，图形界面只有一个固定大小的进度窗口，没有路径选择、路径确认或“更改目录”入口。
- 默认安装位置固定为 `%LOCALAPPDATA%\Programs\零售通`。
- 自定义路径只能通过命令行参数 `/allow-custom-directory` 和 `/install-dir` 实现，普通用户既看不到也不知道。
- 因此“安装路径可选”目前只存在于命令层，不构成真实可用的产品能力，不符合“安装路径必须可选，绝对不能写死”的准则。

#### 2. 自定义路径安装后无法正常卸载

- 曾实际安装到 `D:\Program Files\零售通`，随后从 Windows 应用列表执行卸载。
- 卸载器退出码为 `1`，提示：

```text
拒绝卸载非标准安装目录：D:\Program Files\零售通
```

- 程序目录、开始菜单快捷方式和 HKCU 卸载登记均被保留。
- 根因是安装器和卸载器的路径契约不一致：安装器支持自定义路径并写入 `InstallLocation`，卸载器却曾将默认目录视为唯一合法位置。
- 本地曾做过技术修复和安装/卸载闭环验证，但该结果不代表产品验收通过，也不代表已进入正式交付；本轮按用户要求只保留记录，不再推进 Windows 修复或发版。

#### 3. 安装完成页直接使用系统默认 MessageBox

- 只有一个系统蓝色信息图标、“安装完成”标题和“确定”按钮。
- 没有零售通品牌、图标、版本号或视觉识别。
- 没有展示实际安装路径，用户无法确认程序装到了哪里。
- 没有“立即启动”“打开安装目录”“完成”等正式收尾动作。
- 与零售通主应用界面没有连续性，首次安装体验像调试提示，产品质感严重不足。

#### 4. 没有询问是否立即启动

- 安装完成后直接关闭安装器，没有提供“立即启动零售通”选择。
- 用户安装完仍需自行寻找开始菜单、桌面快捷方式或安装目录。
- 安装器没有记录用户是否选择启动，也没有按选择实际执行。

#### 5. 没有询问是否创建快捷方式

- 开始菜单快捷方式默认自动创建，安装完成页没有告知。
- 桌面快捷方式只有传入 `/desktop-shortcut` 时才创建，普通用户没有选择入口。
- 安装器没有提供“创建桌面快捷方式”“创建开始菜单快捷方式”等明确勾选项。
- 用户不知道该创建哪些快捷方式、实际创建了什么，也无法决定是否创建。

#### 6. 没有产品简单介绍

- 完成页没有一句面向用户的产品简介，用户无法快速知道零售通解决什么问题、适合谁使用。
- 没有说明核心能力，例如本地经营数据分析、销售与库存查看、报表整理等产品定位信息。
- 没有说明适用对象和典型使用场景，首次安装者只能依靠外部文档猜测产品价值。

#### 7. 没有首次使用和数据信任说明

- 没有首次使用路径提示，例如选择工作簿、核对数据、查看分析和导出结果。
- 没有说明数据默认保存在本机、原始文件是否会被修改，以及是否存在联网行为。
- 没有提供隐私、数据归属或备份方面的基本说明，影响用户建立信任。

#### 8. 启动过程明显偏慢，等待反馈不足

- 用户实测启动等待时间明显偏长，启动阶段体感像卡在启动画面。
- 启动页仅显示“零售通”“正在启动本地工作空间…”和“正在准备内置运行环境和本地数据。”，没有阶段进度、耗时信息或可判断是否仍在工作的动态反馈。
- 用户无法区分“正常加载”“初始化较慢”“进程已卡死”和“启动失败”，容易重复点击或强制结束进程。
- 当前没有冻结可比较的启动性能基线，无法说明冷启动、热启动和首次启动分别应在多长时间内完成。
- “启动较慢”目前只是人工验收感知，缺少可重复的测量口径，后续必须补充启动耗时日志和性能验收阈值。

#### 9. 启动后空闲内存占用偏高

- 用户仅启动零售通，没有导入数据、没有执行分析，也没有其他业务操作。
- Windows 任务管理器截图中，“零售通”主进程显示占用约 `55.4 MB` 内存，CPU 为 `0%`。
- 截图拍摄时用户已明确感知内存占用偏高，与“刚启动、空闲、未执行任务”的产品状态不相称。
- 当前不能只依据主进程行得出结论，必须统计零售通完整进程树；如果应用使用 WebView2 等多进程组件，应把其子进程和必要宿主进程明确纳入应用资源口径。
- 当前没有空闲内存基线、静置稳定时间或可接受上限，无法判断该占用是否正常，也无法防止后续版本继续增长。

#### 10. 卸载方式选择界面太 low，选择语义不清且有误操作风险

- 用户明确反馈：“都没选择性，无论是普通卸载还是彻底卸载，貌似我没可选性呢？”这不是单纯按钮文案问题，而是两种卸载方式在界面上都没有形成可独立选择、可确认的入口。
- 用户进入卸载流程后，看到的是系统默认风格的“卸载零售通”弹窗，标题下方只有一个黄色警告图标。
- 弹窗用整段文字介绍“普通卸载”和“彻底卸载”，但没有单选按钮、卡片或明确的当前选中状态。
- 底部只有“是(Y)”“否(N)”“取消”三个系统按钮，用户无法确定“是”对应普通卸载还是彻底卸载，“否”是否代表彻底卸载，抑或只是取消。
- 两种卸载方式的数据影响差异很大，却没有把默认选项、危险操作和推荐操作清楚区分，存在误选彻底卸载、误以为点击“否”只是关闭窗口的风险。
- “卸载程序会尽量将内容移入回收站，以便误操作恢复”只是一句说明，没有展示本次将删除的具体目录、保留的数据范围或回收站行为是否可验证。
- 与安装完成页一样使用未经产品化的系统默认弹窗，整体质感低，和零售通主界面没有品牌连续性。
- 卸载结束后没有任何结果回音，用户无法确认卸载到底成功、失败，还是仍有程序目录、快捷方式、注册项或应用数据遗留。

### 期望结果

安装完成页必须作为正式产品界面设计，至少包含：

1. 零售通品牌、图标和版本号。
2. 实际安装路径，以及“打开安装目录”入口。
3. 路径选择或“更改安装位置”入口；安装前允许用户确认和重新选择。
4. 明确的产品简介，用两到三句话说明零售通是什么、解决什么问题、适合谁使用。
5. 首次使用入口和不超过三步的操作提示。
6. 数据保存位置、原始文件是否被修改、是否联网等信任说明。
7. 明确的安装选项：

```text
□ 立即启动零售通
□ 创建桌面快捷方式
□ 创建开始菜单快捷方式
```

8. 用户选择结果必须被记录并实际执行，不能只显示选项而不生效。
9. 如果开始菜单快捷方式是卸载入口所必需，可以默认勾选，但必须在界面上说明原因。
10. 提供“立即启动”“打开安装目录”“完成”等明确操作。
11. 视觉风格与零售通主应用一致，同时遵循 Windows 原生交互习惯。
12. 支持高 DPI、键盘操作、屏幕阅读器和中文长文本，不出现截断、错位或无法聚焦。

### 启动性能与资源占用期望

1. 由 macOS 主导方定义统一的硬件基线、启动计时口径和可接受阈值，至少区分首次启动、冷启动和热启动。
2. Windows 在同一口径下记录从进程启动到主界面可操作的耗时，并提供可查询的启动日志。
3. 启动页应显示当前阶段或明确进度，例如准备运行环境、加载本地数据、打开工作空间。
4. 超过约定阈值时，应显示“仍在启动”“耗时超出预期”等可理解状态，而不是长时间停留在同一文案。
5. 正常启动不能出现窗口假死、重复启动多个进程或点击无响应。
6. 启动失败时必须给出明确原因和可执行的恢复入口，不能无限停留在启动页。
7. 由 macOS 主导方定义“启动完成后空闲”的判定条件，例如进入主界面后静置固定时间且无后台业务任务。
8. Windows 必须按完整进程树统计零售通及其必要子进程的内存，不能只记录任务管理器中的主进程行。
9. 建立首次启动后空闲、冷启动后空闲和长时间挂起后的内存基线，并设定上限和增长告警。
10. 空闲状态不得持续进行无意义的轮询、预计算、日志刷写或后台数据扫描；确有必要时应说明原因和控制资源上限。

### 卸载方式选择期望

1. 卸载方式必须使用正式产品化界面，不能只用一段说明文字加“是/否”按钮。
2. 普通卸载和彻底卸载必须使用明确的单选控件或独立操作按钮，名称、说明和当前选中状态一目了然。
3. 用户必须能分别选择普通卸载或彻底卸载，并在确认前看到当前选择；不能出现两种方式“都没得选”或选择后行为仍不明确的状态。
4. 默认选中普通卸载；彻底卸载必须作为高风险操作单独强调，并需要二次确认。
5. “是/否”不能承担两种业务方式的映射，按钮文案必须直接表达动作，例如“普通卸载”“彻底卸载”“取消”。
6. 卸载前必须展示本次会删除的程序目录、快捷方式、注册项、应用数据、历史、缓存和日志范围，以及明确会保留的原始资料和用户文件。
7. 只要涉及用户资料，必须默认保留；无法恢复的数据必须单独警示，不能以“尽量移入回收站”代替确定的数据保护策略。
8. 卸载完成或失败后都必须给出明确结果、实际影响范围和可执行后续操作，不能静默关闭。
9. 卸载结果必须列出本次已删除内容、已保留内容、清理失败项和日志位置，并明确提示用户是否仍需手工处理。

### 验收要求

- 安装成功、安装失败、覆盖升级完成和卸载确认均不得以裸 `MessageBox` 作为正式产品界面。
- 普通 GUI 安装必须真的可以选择安装路径，不能只提供命令行参数。
- 安装器允许的路径，卸载器必须能够识别并卸载。
- 勾选或取消快捷方式后，文件系统结果必须与选择一致。
- 勾选“立即启动零售通”后应用必须成功启动；取消后不得自动启动。
- 完成页必须显示实际安装路径，并提供打开安装目录入口。
- 首次安装用户仅阅读完成页即可知道产品用途、下一步操作和数据保存方式。
- 用户关闭完成页后不得留下后台安装进程。
- 启动耗时可被重复测量，首次启动、冷启动和热启动均达到 macOS 主导方确认的阈值。
- 启动页能够明确反映加载仍在进行；超过阈值或启动失败时不得长时间无变化。
- 启动后空闲内存按完整进程树统计，不得超过 macOS 主导方确认的基线；静置期间不得持续明显增长。
- 卸载方式选择不得使用“是/否”映射普通卸载和彻底卸载；两种方式的差异、默认选项和数据影响必须清晰可见。
- 普通卸载和彻底卸载必须分别可选中、可确认；用户看到的选择、确认页摘要和最终实际执行行为必须完全一致。
- 彻底卸载必须二次确认，并保证原始资料和 Documents 下的用户文件不会被删除；回收站处理结果应可验证。
- 卸载结束后必须明确显示成功或失败、已删除内容、已保留内容、失败项和后续处理方式，不能无提示关闭。
- 安装器视觉和交互由 macOS 主导方统一制定跨平台基线，Windows 按 Windows 原生规范实现，不能各自临时发挥。

### 产品准则

**安装器是用户第一次接触产品的界面，不是系统工具的附属品。**  
安装、升级和卸载流程必须达到正式产品交付质量，不能用默认系统弹窗、调试文案、隐藏命令行参数或临时按钮替代。

**安装自由，卸载方便。**  
用户可以自主选择安装位置和快捷方式；安装完成后应能立即启动；卸载应能通过系统应用管理或开始菜单等常规入口一次完成，不要求用户查找目录或手工执行命令。

| 卸载结果反馈 | 成功或失败有明确结果，已删除和已保留内容可见 | 必测 | 必测 |
| 普通卸载 | 无需手工删目录，程序入口和注册信息完整回收 | 必测 | 必测 |
| 完整卸载 | 清理范围明确，用户资料不会被误删 | 必测 | 必测 |
| 卸载失败提示 | 原因明确、可操作、返回非零退出码 | 必测 | 必测 |

## 给 macOS 主导方的复评点

以下只作为跨平台验收输入，具体 macOS 实现由 macOS 主导：

- 如果允许用户选择自定义安装位置，卸载器必须从实际 App Bundle 位置或系统登记信息解析路径，不能假定固定位于 `/Applications`。
- 如果 macOS 产品策略只允许 `/Applications`，则安装界面和说明必须明确，不允许出现“可选路径”但实际上不支持的状态。
- 删除 App Bundle、LaunchAgent、登录项、偏好设置、缓存和日志时，应逐项定义普通卸载与完整卸载范围。
- 卸载入口应保持常规、直观，不要求用户打开终端手工删除。
- 启动性能必须定义统一的测试设备基线、计时起点、计时终点和首次/冷/热启动阈值，不能只以“感觉不慢”验收。
- 卸载方式必须提供真实、互斥且可确认的选择，不能只显示两段说明后用“是/否”让用户猜；确认页和实际执行结果必须一致。
- 卸载完成必须给出明确结果和清理清单，不能关闭弹窗后让用户自行判断是否成功或是否仍有数据遗留。

## 后续强制回归

任何平台发布前必须至少完成：

1. 默认路径安装、启动、升级、卸载。
2. 自定义路径安装、启动、升级、卸载。
3. 含空格及中文路径的同类闭环。
4. 普通卸载与完整卸载的数据保留边界。
5. 安装器允许的路径与卸载器允许的路径一一对应。
6. 安装完成页的品牌、版本、实际安装路径、产品简介和首次使用提示均可见且完整。
7. “立即启动零售通”的勾选与取消结果均实际生效。
8. 桌面和开始菜单快捷方式的勾选、取消结果均与实际文件系统一致。
9. 首次启动、冷启动和热启动分别记录耗时，均在约定阈值内，且启动页没有无反馈假死。
10. 启动后静置时按完整进程树记录内存、CPU 和磁盘占用，均不得超出约定基线。
11. 普通卸载和彻底卸载分别走完整真实流程，确认两种方式都能被明确选中，且界面摘要、实际清理范围和保留数据完全一致。
12. 卸载完成后核对结果页、文件系统、快捷方式和 HKCU 卸载项，确认成功、失败和遗留内容都有明确反馈。

未完成自定义路径真实卸载验证的安装包，不得标记为安装/卸载验收通过。
